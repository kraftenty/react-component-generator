# PR 템플릿 (한국어)

한국어 프로젝트에 사용한다. 모든 섹션을 채우고, 해당 사항이 없으면 "해당 없음"으로 남긴다.

## 제목 규칙

- 형식: `<type>: <요약>` (type은 `feat`, `fix`, `refactor`, `chore` 등 저장소 컨벤션을 따른다)
- 한국어로 70자 이내, 마침표 없음
- "무엇을 했는가"를 명사형 또는 `~추가`, `~수정`, `~개선` 형태로 쓴다
- 좋음: `feat: 프롬프트 500자 제한 검증 추가`
- 나쁨: `여러 가지 수정함.`

## 본문 템플릿

```markdown
## 개요

<이 PR이 무엇을 왜 하는지 1~3문장. 배경과 목적 중심으로 쓴다.>

## 변경 사항

- <핵심 변경 1>
- <핵심 변경 2>

## 변경 유형

- [ ] 기능 추가 (feat)
- [ ] 버그 수정 (fix)
- [ ] 리팩터링 (refactor)
- [ ] 설정/문서/기타 (chore)

## 테스트

- [ ] 단위 테스트 추가 또는 수정
- [ ] 로컬에서 테스트 실행 통과
- [ ] 수동 확인

<실행한 명령과 결과, 확인한 시나리오를 적는다. 실행하지 않았다면 "미실행"이라고 쓴다.>

## 리뷰 포인트

<리뷰어가 특히 봐 주었으면 하는 부분, 트레이드오프, 고민한 지점. 없으면 "해당 없음">

## 관련 이슈

<Closes #번호. 없으면 "해당 없음">

## 스크린샷

<UI 변경이 있으면 전후 비교. 없으면 "해당 없음">
```

## 작성 지침

- 변경 사항은 "무엇이 바뀌었나"를 파일 단위가 아니라 동작 단위로 쓴다.
- 변경 유형과 테스트의 체크박스는 실제로 해당하고 확인한 것만 `[x]`로 바꾼다.
- 호환성을 깨는 변경(breaking change)이 있으면 개요 바로 아래에 `**주의:**`로 명시한다.
